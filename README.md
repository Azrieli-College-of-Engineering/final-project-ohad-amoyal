מסלול נבחר: מסלול א' - מחקר ומימוש מתקפה POC 

תיאור הפרויקט
בפרויקט זה בחרתי לחקור את חולשת ה-JWT Authentication Bypass. מטרת הפרויקט היא להראות איך הגדרות לא נכונות במימוש של אסימוני JWT יכולות לאפשר לתוקף לעקוף מנגנוני הזדהות ולהשיג הרשאות ניהול (Admin) במערכת.

הרקע התאורטי והחולשה
אסימוני JWT מורכבים משלושה חלקים: Header, Payload ו-Signature. החולשה שאני מדגים נובעת מכך שהשרת לא מגביל את סוג אלגוריתם החתימה המותר.
זה מאפשר לתוקף לשנות את ה-Header לאלגוריתם none. במצב כזה, חלק מהספריות יקבלו את הטוקן כחוקי גם בלי חתימה, מה שמאפשר לי לשנות את התוכן של הטוקן (למשל לשנות את התפקיד ל-admin) ולעקוף את האבטחה.

מבנה הפרויקט
app.py: השרת הפגיע (רץ על פורט 5000).

secure_app.py: השרת המאובטח עם מנגנוני הגנה (רץ על פורט 5001).


exploit.py: סקריפט התקיפה שמנצל את החולשה.


מדריך הרצה - שלב אחר שלב
1. התקנת ספריות
יש להריץ בטרמינל:
pip install flask pyjwt requests

2. הרצת המתקפה (הוכחת חולשה)
מריצים את השרת הפגיע: python app.py.

בקובץ exploit.py, מוודאים שהכתובת היא http://127.0.0.1:5000.

מריצים את הסקריפט: python exploit.py.

התוצאה: השרת יאשר את הטוקן המזויף ויציג הודעת "Welcome Admin".

3. בדיקת ההגנה (מניעת החולשה)
מריצים את השרת המאובטח: python secure_app.py.

בקובץ exploit.py, משנים את הכתובת ל-http://127.0.0.1:5001.

מריצים שוב את הסקריפט: python exploit.py.

התוצאה: השרת יזהה ניסיון תקיפה ויחזיר הודעת שגיאה.

מנגנוני הגנה
כדי למנוע את החולשה, הוספתי בשרת המאובטח הגבלה שמכריחה שימוש באלגוריתם חתימה ספציפי (HS256) ובדיקה קשיחה מול המפתח הסודי של השרת.
